# 商品上架表（类 Excel 编辑 + 行内生成）

供应商数据只有一个落点：**商品上架表**（`/product-grid`）。原「供应商上传」页已并入本页，
旧地址 `/supplier-upload` 重定向到这里；上传只是表格的一个导入动作，不再是独立流程。

自研表格（`ExcelGrid.vue`）而非 Handsontable：非商业授权对后续商用是隐患，而本项目需要的
粘贴、虚拟滚动、左右冻结、外置滚动条都能用 CSS/组件自身解决。

## 1. 模块边界

| 模块 | 只做 | 文件 |
|---|---|---|
| 页面 | 测量、装配、导入、行内生成、翻页决策 | `views/ProductGrid.vue` |
| 状态机 | 基线/脏数据/新增/删除/粘贴/导入/保存/字段写回 | `composables/useProductGrid.ts` |
| 选区 | 矩形选区、扩展、矩阵导出 | `composables/useGridSelection.ts` |
| 剪贴板 | TSV 语义、复制/剪切/粘贴、按键 | `composables/useGridClipboard.ts` |
| 服务端协议 | 分页、3 秒缓存、请求编号 | `composables/useGridQuery.ts` |
| 模型 | 字段目录、表头别名、空行、签名、布局修复 | `utils/gridFields.ts` |
| 布局存储 | 按「表格 + 用户」私有化 | `utils/layoutStorage.ts` |
| 渲染 | 虚拟滚动、冻结列、编辑、操作列 | `components/grid/ExcelGrid.vue` |
| 生成 | 流式调用、超时、降级、字段映射 | `composables/useListingGeneration.ts` |
| 生成页数据 | 读取表格行、写回、可编辑判定 | `composables/useGridProducts.ts` |

## 2. 三份数据

```
服务端页（只读快照）
  → rows      （唯一编辑源，含末尾草稿行）
baseline      （id → 业务签名 + 原始行）
  ├─ dirty / summary
  ├─ 删除集合 = baseline − 当前非空行
  └─ discard = 用 baseline 重建
```

- `rowSignature()` 只序列化行自身的字段（键排序），**不读列模型**：导入新增一列不会把所有行
  误判成「已修改」。
- 空白行只存在于 `rows`，不进 baseline、不计 dirty、不保存、不可删除。
- 删除是**草稿状态**：`deleteRows()` 只把行从 `rows` 移除，`deletedIds = baseline − 当前非空行`
  随 dirty 汇总（`删除 N`）；只有点击保存时 `savePage()` 才把 `deletedIds` 发给批量接口。
  `discardChanges()` 用 baseline 重建，已标记删除的行会恢复，不需要撤销接口。
- 行 id 由客户端生成（`p_<ts>_<rand>`），新增行保存后不需要重取列表。

## 3. 列模型

核心列（顺序即默认显示顺序）：

| 列 | key | 说明 |
|---|---|---|
| 商品名称 | `productName` | 供应商商品名，**导入必填** |
| SKU / 商品编号 | `sku` | **导入必填**；`商品编号/产品编号/货号/Item No.` 等都映射到这一列 |
| 产品标题 | `title` | 生成结果 |
| 类目 / 价格 / 币种 / 起订量 / 供应商 | `category` / `price` / `currency` / `moq` / `supplier` | 可选来源信息 |
| 详情描述 | `description` | 生成结果（原「描述」列） |
| 五点描述 | `bulletPoints` | 生成结果，单元格内以换行分隔 5 条 |
| 关键词 | `keywords` | 生成结果，逗号分隔 |

「操作」列是**结构列**，不属于字段模型，永远冻结在最右侧：`保存`（绿色勾选图标，单行落库）、
`生成`（蓝色魔法棒图标，与 Listing 生成器一致，弹出 7 语种环形菜单）与 `删除`（红色垃圾桶图标，
标记为待删除，点击保存后才真正落库）。三个按钮都是图标按钮，标签走 i18n 显示在主题化 tooltip 中。
行号列冻结在最左，
两列都从 `ExcelGrid` 的几何计算里占位，所以数据列的左/右冻结偏移不会与它们重叠。

操作列的 z-index（3）低于 sticky 表头（20），所以数据行向上滚动时操作单元格会从表头下方滑过，
不会把「操作」表头盖住。表头（含行号、左右冻结列的操作/列标题）是同一个纵向 sticky 表头：
上下滚动数据时保持固定，左右滚动时行号与冻结列也各自贴边。

行号列的另一个入口：**双击序号**打开该行的商品信息弹窗（`ProductInfoDialog`）。弹窗按完整字段
目录渲染，所有列都可编辑；点「保存」会先把值写回该行，再立即调用单行保存，不需要再点工具栏
「保存」。只读行（他人创建、非管理员）弹窗中禁用输入并给出提示。双击识别用 pointerdown 计时，
因为行号单元格为了防止拖选文本而 `preventDefault()`，依赖 `dblclick` 在该场景不可靠。

所有悬浮提示使用全局 `v-tooltip` 指令，而不是浏览器原生 `title`：原生 title 是系统绘制的纯黑浮窗，
不跟随暗色/亮色主题；`v-tooltip` 使用主题变量、自动避让视口边缘，并在挂载时移除残留的 title 属性。

### 分页

服务端分页，页大小可选 `20 / 50 / 100 / 200 / 500`，默认 `100`。页码与页大小都在工具栏：
页大小变化会先走与翻页相同的脏数据确认（保存 / 放弃 / 取消），成功后回到第 1 页；服务端
返回的 `itemsPerPage` 会回写，避免前后端钳制值不一致。切换页大小时查询缓存键包含
`pageSize`，不会命中旧页的缓存。

上传文件里多出来的表头仍然作为「上传列」追加在末尾（上限 20 列），不丢数据。

## 4. 导入

两个入口，同一套逻辑：

- 工具栏「导入表格」按钮 → 隐藏 `<input type=file>`；
- 把文件拖到表格区域 → 松开即导入（拖拽时显示虚线提示层）。

解析仍走 `POST /api/upload-supplier`（与旧上传页同一解析器，服务端去掉标题行/转置/空列）。

导入时先做表头映射（`normaliseImportRecord`）：常见中英文字段名归一到核心列，例如
`商品名称/产品名称/name → productName`、`SKU/货号/商品编号/商品编码/产品编号/Item No. → sku`、
`描述 → description`、`五点描述/卖点 → bulletPoints`；未识别的表头原样保留为上传列。

校验只有一条规则：**`sku` 与 `productName` 必须非空**。标题、类目、价格等不再拦截导入——
它们本来就可以由生成器产出。缺列的行跳过，并在「导入结果」弹窗里按行号列出原因。

导入成功后调用 `saveAll()` 直接落库（按当前页大小分批，最多 500 行/批），所以刷新后数据仍在，
可以紧接着在表格里生成。`saveAll()` 会先同步刷新脏数据统计：summary 是 120ms 防抖的，否则
刚导入的行会被误判为「无改动而不保存」。

## 5. 行内生成

点击某行「生成」→ 环形菜单选择语种 → 调用 `/api/generate-listing/stream`（非管理员走演示
数据）→ 结果**写回同一行**的 `title` / `description` / `bulletPoints` / `keywords`，并立即
保存该行（行级 loading，不遮全表，成功后行心跳高亮）。

- 未配置模型：提示并跳转模型管理，不发请求。
- 生成超时（120s）或流式失败：自动降级为普通 POST；仍失败则提示，不写脏数据。
- 发给模型的 `productData` 只包含来源字段（`sourceFields()` 排除生成结果），重复生成不会把上
  一轮生成内容当成输入。

平台（Amazon/Shopify/eBay/Etsy）在页面右上角选择，作用于该页所有行内生成。

## 6. Listing 生成页

同一批行，另一种工作方式：左侧列表来自 `GET /api/products`（不再读上传缓存），因此两页永远
看到同一份数据。

页面是标准的主从布局：**商品列表 / Listing 预览 + SEO / AI 对话**三列。商品列表本身就是商品
切换器——点击任意商品卡片，中间预览和右侧对话就切到该商品，效果与旧版页签完全相同，但不再
单独占用一列导航；省下来的横向空间全部给中间预览。

- 生成过的商品是深绿色卡片，未生成的是浅绿色；当前预览的商品带高亮描边和「预览中」标记；
- 点击未生成的商品会清空预览并显示该商品的空状态，提供「立即生成」按钮，不会继续显示上一个
  商品的 Listing；
- 对话按 Listing id 分线程（`chatStore.threads`），切换商品时先收起当前线程、恢复目标商品的
  线程，所以每个商品的对话互不串台；
- 单行生成：结果写回表格行，并同步到右侧预览；生成开始时会自动把列表高亮切到该商品；
- 批量生成：勾选若干行 + 选择语种，顺序生成，逐行写回，顶部显示 `已完成/总数`，结束汇总
  成功/失败数；
- 只读行（他人创建、非管理员）不可勾选、不可生成，避免批量结束后才发现写入被拒；
- 点击商品的「详情」按钮仍是打开只读商品信息弹窗（与上架表的双击序号弹窗共用
  `ProductInfoDialog`）。

## 7. 数据契约

```http
GET /api/products?page=1&pageSize=100&q=关键词
→ { items: Row[], totalItems, currentPage, itemsPerPage, totalPages,
    tableMissing?, ephemeral? }

POST /api/products/batch          # 需要登录
{ items: [{ id, fields }], deletedIds: [...] }
→ { saved: Row[], deleted: string[], rejected: [{ id, reason }] }
```

- **删除幂等**：删除不存在的 id 返回成功，这是客户端补删重试的前提。
- **整行接受或整行拒绝**：单行校验失败进 `rejected`，不会写半行。
- **200 不等于成功**：写回生成结果时必须检查 `rejected`/`saved`，否则会把别人的行当作
  「已生成」。
- **所有权**：非管理员只能写自己创建的行；越权写进 `rejected`，越权删静默无效。

本地 Express 没有 D1，商品表走进程内存（工具栏显示「内存模式」），重启即清空；生产走 D1。

## 8. 验收清单

**首帧**：表头与草稿行先于数据出现，无高度跳变。

**导入**：按钮与拖拽都能导入；中文字段映射到核心列（`商品编号` 也算 SKU）；未知表头成为上传列；
缺 SKU/商品名称的行被跳过并列入报告；导入后刷新仍在；已有行不被误删。

**行内生成**：未配置模型时跳转；环形菜单 7 个语种且 Esc 关闭；生成结果写回并落库；他人行
不可生成。

**批量生成**：勾选只对可写行生效；逐行写回；结束汇总成功/失败。

**保存/删除**：单行保存不遮全表；纯修改保存后不闪屏；删除先进入草稿状态（行从表格消失、
工具栏显示「删除 N」），点击保存后才调用批量接口，放弃修改可恢复；保存后不影响其他行。

**布局**：隐藏/重排/冻结刷新后保持；左右冻结合计不超过可见列数；行号列在横向滚动时
不移动，表头在纵向滚动时不移动。

**分页**：可选 20/50/100/200/500，默认 100；切换前有脏数据确认，成功后回到第 1 页；
前端页码/页大小与服务端返回一致。

**多语言**：工具栏、行操作、列设置、导入报告与分页文案全部走 i18n；核心列标题按语言
显示，上传列保留原始表头；操作列图标按钮的标签通过主题化 tooltip 展示。

**悬浮提示**：全站不再出现浏览器原生黑底 title 浮窗；表头、单元格、图标按钮的提示使用
主题色 tooltip，并能自动避开视口边缘。

## 9. 已知限制

- 行高固定 30px：五点描述在格内是单行省略，双击编辑或导出 CSV 才能看到全部 5 条。
- 粘贴上限 1MB、导入上限 10MB（服务端 multer 限制）。
- 单次保存按当前页打包（页大小可选到 500），慢网络下大批量保存耗时更长。
- 数字规范化只处理货币符号/单位后缀/千分位；欧洲式 `1.234,50` 判为非法而不是猜。
- 多标签同时编辑同一页时不做实时协同，后保存者覆盖。
- 删除、修改、新增在点击保存前都只是当前页草稿：刷新/关闭页面会丢失；翻页或改页大小前
  有保存 / 放弃确认。
- 批量生成是串行请求，行数很多时耗时线性增长；没有队列/后台任务。
